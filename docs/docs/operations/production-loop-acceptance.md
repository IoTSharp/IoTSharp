# 生产闭环验收

本清单用于一个已批准的真实业务范围。平台 API、SQLite 集成测试、模拟预览和进程健康都不能单独证明生产完成。按 O1→O4 顺序保留证据；任一步缺证据就停止生产推进，RuleChain 增强留待 O4 验收后。

## 本次基线（2026-10-03）

基线提交 `f1f112b2` 已包含 Product 能力字典与命令、Device Product 绑定、Asset 点位关系、Edge 注册/心跳/能力、采集模板与不可变版本、发布确认及回滚。它们表示可用能力，不表示已有现场验收。

本轮未提供生产地址、租户授权、现场设备清单或执行端日志，O1～O4 均不能标记生产完成。下面的配置回滚和资产绑定修复只是消除已识别的控制面缺口。

本地验证：SQLite 应用集成、Edge 运行时输入校验和合同序列化共 39 项测试通过。覆盖资产空点位拒绝、有效关系持久化和去重、不同配置版本回滚的正文/哈希与当前目标收敛、匿名回执认证及直连 Device OTA 权限边界。这些回执由测试客户端生成，属于本地集成验证，不是现场执行端证据。PostgreSQL、SonnetDB 及真实运行时尚未在本轮验证。

## O1：确认业务模型

保存批准人、批准时间、业务范围和责任人。记录 Product ID、能力项（名称、类型、单位、采样与质量语义）、Asset ID 与实际对象、Device ID 与 Product/Asset 关系。Tenant/Customer 只是技术归属，不能代替现场责任确认。

通过 Product、Device、Asset 查询接口核对同一租户/客户及未删除状态；`/api/Asset/Relations?assetid=...` 应返回实际 Device 及点位。当前 Asset 使用属性/遥测点位关系，尚不提供独立的无点位设备绑定、业务层级或负责人模型。空点位请求必须失败，不能把一次成功响应当绑定完成。

## O2：确认真实运行时

执行端使用自己的令牌调用 `/api/Edge/{access_token}/Register`、`Heartbeat` 和 `Capabilities`。保留实例身份、版本、平台接收时间及执行端日志；只保存令牌脱敏后的路径。

使用管理端 `/api/Edge/{id}/RuntimeStatus` 与 `/Capability` 交叉核对。事先批准心跳观察窗口、最大间隔与时钟误差，在窗口内保存多次连续报告。实际执行一条诊断任务，关联任务 ID、受理回执、执行端日志、结果回执和平台审计。注册或心跳成功不替代诊断执行证据。

匿名运行时调用 `/api/EdgeTask/Receipt` 必须携带 `X-Edge-Access-Token`，令牌须属于任务的通道设备。Gateway 可处理其正式任务；直连 Device 仅可处理以自身为目标的脚本或固件 OTA，不能接管 Gateway 配置或诊断。已认证的 NormalUser 保留同租户、同客户的管理端回执入口；此类人工回执不能作为执行端证据。过去未携带令牌的匿名客户端需更新请求头。

## O3：确认配置收敛

批准 Collection Template 点位、转换和映射后保存不可变配置版本。记录版本 ID、正文 SHA-256、来源与批准引用；避免把设计器的固定预览值当现场试读。

执行端通过 `/api/Edge/{access_token}/CollectionConfig/Pull` 拉取目标配置。关联 Active assignment、下发任务 ID、执行端实际加载的版本/哈希、回执和 `/api/Edge/{id}/CollectionVersionStatus`。要求当前版本与目标版本一致，并从真实点位采集结果核对单位、质量及时间戳。仅回执 Succeeded 不足以完成 O3。

## O4：受控灰度与回滚

1. 保存明确目标列表、不可变前向版本和不同的回滚基线版本、批准人、成功阈值、观察窗口、暂停条件及回滚触发条件。
2. 创建 `/api/ReleaseCenter/Plans`，使用人工确认策略先投递批准的灰度批次。保存计划、任务、回执与审计；观察窗口内核对实际点位和执行端版本后，才批准后续批次。
3. 回滚前核对已下发的前向任务已终结；平台取消未执行任务不能证明执行端已停止，必要时先从运行时确认取消。
4. 调用计划回滚接口，保存基线版本 ID、回滚任务与执行端日志。重新拉取配置并核对 Active assignment 指向基线，当前/目标版本及哈希收敛。
5. 回滚后再次核对真实采集、告警及诊断结果，证明没有旧前向任务重新覆盖。归档全部证据后由责任人确认完成。

当前控制面会拒绝存在在途配置任务的回滚，但检查与目标分配尚无跨请求互斥。一次验收只允许一个操作者向同一 Gateway 下发配置；暂停其他发布计划、模板发布和配置保存入口。此操作约束不能证明并发安全，多操作者并发生产发布仍需单独实现与验证互斥机制。

## 证据记录

每个阶段记录：业务范围、租户/客户、对象 ID、批准引用、UTC 时间窗口、平台任务/回执/审计 ID、执行端实例与日志引用、配置版本/哈希、现场结果、验收人及结论。证据分类使用“本地集成验证”“执行端声明”“现场交叉验证”，不把前两类自动提升为后一类。

不在仓库记录访问令牌、密码或完整敏感点位值。原始证据保存在经批准的位置，仓库仅保留脱敏摘要与可追溯引用。失败、缺失或超时应明确记录，不填充模拟数据补齐。
